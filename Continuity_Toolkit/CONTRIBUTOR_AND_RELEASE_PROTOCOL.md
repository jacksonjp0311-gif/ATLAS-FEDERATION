# ATLAS FORGE — contribution, correction and release governance

1. **Never rewrite old scientific record/relation bytes.** Add new revisions with fresh canonical digests and preserve old releases.
2. **No concealed domain branch.** New content enters the single canonical common registry, or a clearly auxiliary tool release attached to it. The original 30-domain queue must not be silently overwritten.
3. **Separate evidence grades.** Mathematical derivation, independently coded finite oracle, lab measurement, and externally reproduced physical demonstration are four different statuses.
4. **Source rights and provenance.** Capture original publisher bytes only when lawful; preserve exact edition, checksum, review and original license. Do not mirror restricted full texts into public bundles.
5. **Include counterexamples.** Model limitations, exceptions, failed experiments and unresolved uncertainty are permanent, discoverable evidence.
6. **Release gates.** Historical byte preservation; structural schema; all prior test suites; new negative tests; independent oracle; deterministic delta patch; exact clean restoration; full manifest; independent replay; Library upload/readback; checkpoint LAST.
7. **Do not grant authority by metrics.** Number of chapters, citations, tests, model tokens or agent scores is not itself a scientific credential.
8. **Maintain practical offline access.** Plain-text instructions, standard-library tools, a searchable static portal, and verified redundant copies are first-class outputs.
9. **Security is a separate gate.** A SHA-256 digest is not a signature. True authenticity requires independently maintained trusted keys and secure validation/rotation procedures.
10. **Scope safety.** Never treat a reconstruction reference as permission or technical qualification to run hazardous experiments, medical procedures or safety-critical systems.
