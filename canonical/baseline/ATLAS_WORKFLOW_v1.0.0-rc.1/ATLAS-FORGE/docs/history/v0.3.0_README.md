# ATLAS FORGE

### One hub. Independent scientific knowledge nodes. Evidence preserved.

**v0.3.0 · Node Federation · James Paul Jackson · 11 November 2026**

Your existing Atlases now sit behind one local reference interface. Signal Atlas and Cymatics Atlas remain independent projects with their own identities and versions. Forge contains **pinned, byte-checked copies of their reference data**, not just bookmarks. Measurement Atlas remains a clearly labeled starter node.

## How the nodes fit together

```text
ATLAS FORGE
  ├── Signal Atlas       reference node, pinned to its published source
  ├── Cymatics Atlas     reference node, pinned to its published source
  └── Measurement Atlas  starter node, explicit opt-in for retrieval
```

A question about frequency and uncertainty can retrieve context from both published libraries in one request. A Faraday-wave question can retrieve Cymatics records. Every result retains its node identity, original record, source links, version, assumptions where provided, limitations, and evidence labels.

This is an **offline reference federation**, not a merger of the upstream applications. Their simulators, full websites, research PDFs and raw experimental datasets are not copied into this package. The public repositories are unchanged. Forge does not install itself into PEGASUS or any other agent.

## Quick start

Extract this package and open PowerShell in its root:

```powershell
py -3 -m pip install -e .
py -3 -m atlas_forge nodes
py -3 -m atlas_forge verify-nodes
py -3 -m atlas_forge search "frequency uncertainty"
py -3 -m atlas_forge search "Faraday waves" --node cymatics-atlas
py -3 -m atlas_forge serve
```

Open **http://127.0.0.1:8766** for the node portal and shared search. The service binds only to `127.0.0.1`, has no write routes, and does not run upstream code. Stop it with Ctrl+C. `START_FORGE.cmd` launches directly from source without installing dependencies; Python 3.10+ is required.

Starter queries require an explicit opt-in:

```powershell
py -3 -m atlas_forge search "uncertainty" --node measurement-atlas --include-starters
```

## One connection for compatible applications

```python
from atlas_forge.federation import Federation

forge = Federation()
print(forge.discover())
context = forge.search("frequency uncertainty", per_node=3)
for group in context["groups"]:
    for record in group["results"]:
        print(group["node_id"], record["title"], record["upstream_status"])
```

The same context is available at `GET /api/search?q=frequency%20uncertainty` after starting the local service. Discovery is `GET /api/nodes`. A portable JSONL export works without a running server:

```powershell
py -3 -m atlas_forge export-nodes --out reference_nodes.jsonl
```

Exports refuse to overwrite an existing destination. See the [complete interface contract](docs/NODE_INTEGRATION.md). Native Forge MCP is not implemented in this release; do not confuse an upstream Atlas's MCP adapter with a tested Forge MCP endpoint.

## What integrity means here

The registry pins each node manifest. Each manifest pins every raw reference file by SHA-256, and the six published data files also match GitHub's Git blob hashes at the recorded commits. A damaged node is excluded with an explicit error; healthy nodes remain queryable. A changed registry is rejected.

Checksums are consistency checks, not digital signatures or scientific review. The upstream Signal label `verified` is preserved as an **upstream label**, while Forge adds `imported_reference_not_independently_reviewed`. No record is automatically promoted to independent validation.

A matched record is returned as **partial context**, never a certified answer. Lexical matching has no general semantic sufficiency guarantee. Shared citations are surfaced as shared dependencies, not counted as independent corroboration. A record locator identifies a stored record; it is not silently presented as an exact passage in a scientific paper.

## Existing builder still works

```powershell
py -3 -m atlas_forge rank
py -3 -m atlas_forge init measurement --out output
py -3 -m atlas_forge validate output/MEASUREMENT-ATLAS
py -3 -m atlas_forge query examples/MEASUREMENT-ATLAS "uncertainty"
```

Generating a scaffold does not research a new domain. Upstream reference snapshots are frozen and do not synchronize automatically. New revisions should be staged and checked, then explicitly pinned in a new release. Preserve previous editions and never silently switch a pin to a moving branch.
